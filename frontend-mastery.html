What you'll build

Twelve small builds that turn out to be one product.

The project: a job board, engineered

Every module ships its own small, finishable piece — a utility library, a component, a data layer, a rendering strategy. They're not disconnected demos: each one is a slice of the same product, so by module 12 you assemble them into a real application instead of starting from an empty folder.

A job board earns its place: a listings feed that needs virtualization, search that needs debounce and autocomplete, filters that belong in the URL, applications that need optimistic updates, public pages that need SEO and a dashboard that needs auth. It's also the exact shape of the system-design questions in module 11.

Ships along the way
  • M3 — a tested utility library: debounce, throttle, deepClone, curry, EventEmitter, Promise.all
  • M4 — the typed domain model: jobs, employers, applications, with schema validation
  • M5 — the listings feed in React, rendered and profiled
  • M6 — typed primitives: buttons, fields, variants, generic components
  • M7 — the gauntlet: search autocomplete, filter dropdown, apply modal, tabs, toasts, virtualized list
  • M8 — the data layer: caching, optimistic apply, filters as URL state
  • M9 — the Next.js version: public SEO pages vs authenticated dashboard
  • M10 — a measured before/after, plus a real test suite in CI
  • M11 — six system design write-ups, including one for this product
  • M12 — the assembled app, deployed, with the architecture story written

Every exercise comes as three branches

  • Starter — the scaffold and the failing tests. Nothing else.
  • Guided — the same, plus TODOs, hints and the reasoning, for when you're stuck.
  • Solution — the finished implementation, so you can diff your work against mine.
Struggle first, hint second, compare third — the order that actually builds recall.

What you end up with

  • A public repo with a clean commit history
  • A live URL that holds a performance budget
  • Ten standalone artifacts you can talk through in an interview
  • One product you can defend end to end

Questions

Do I need frontend experience?

No. You need solid knowledge of any programming language and basic HTML/CSS exposure. We rebuild the browser and JavaScript layer properly before React appears in module 5.

Isn't this just another React course?

React is 2 of 14 modules. The program is the browser, JavaScript, TypeScript, data architecture, rendering strategy, performance, testing, security, system design and the interview itself. A React course teaches you to build a screen; this teaches you to be the engineer who owns it.

What about AI? Everyone says frontend is being automated.

AI writes components. It doesn't decide where the boundary goes, which state is server state, or why your INP is 400ms — and interviewers know it. Catalyst teaches the AI workflow in its own program, AI for Frontend. This one builds the engineering judgment that makes that workflow safe.

What is the mock interview exactly?

A recorded interview in the format top companies use — a live coding round and a frontend system design round — followed by written feedback on what to fix before the real thing.

Recorded or live?

Recorded so you move at your own pace, with new modules dropping weekly during pre-order, plus a weekly live Q&A session and a WhatsApp support group.

Why pay when YouTube is free?

YouTube has every topic and no order, no rubric, no one grading whether your answer would pass. What you're buying is sequence, depth, and the interview layer — the drills, the question banks and the mock — which don't exist for free in Arabic.

What if I change my mind?

7-day money-back guarantee. One WhatsApp message, no forms.
